# Project Lessons

* Keep public-sector product claims bounded: use measured language, label fictional data, and avoid implying replacement of authoritative city systems.
* Treat accessibility, governance, privacy, and human authority as product requirements rather than supporting copy.
* Add and verify `.gitignore` before the first application commit so dependency and build directories are never staged.
* Apply Markdown list conventions only to Markdown files; GitHub Actions step arrays require YAML hyphens. Run a workflow syntax validator before pushing.
* Use the approved full solution-domain name in navigation labels when stakeholders specify it; do not shorten public-safety and emergency-coordination terminology.
